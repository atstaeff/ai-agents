# Repository Contribution

1. Reuse applicable AGENTS.md and process instructions already loaded. For unfamiliar
   substantial work, read their context/process entry: outcome, scope, decision owner,
   work/review homes, knowledge and relevant accepted decisions. Create no onboarding
   report, YAML manifest or project skeleton. A clear small correction goes directly
   through affected-file inspection, change and verification. For wording-only changes,
   verify exact content/diff; use application tests only for affected behavior or an
   explicit project requirement for this kind of edit. A runbook listing available test
   commands does not alone require running them for a wording correction.
2. Read required source bodies, not every linked document. For adopted web policy,
   record the actual source revision when consequential. If access is unavailable,
   identify the URL and affected work; use only a declared versioned fallback and
   continue independent authorized work. Never substitute remembered policy or a tracker.
3. Inspect the affected source, real setup/check commands, CI and existing assignment.
   Identify owner, bounded writer scope, dependencies and integration responsibility.
   Preserve others' work; coordinate shared interfaces and overlapping writes.
4. Load the next skill only for an unresolved activity: product-discovery for uncertain
   value/scope, architecture-planning for system tradeoffs, the relevant language skill
   for implementation, or testing/code-review for verification. Read its body explicitly;
   a link does not install tools, trigger delegation or require a new session.
5. Implement and verify within existing scope and permissions. Preserve required plan
   approval, human feedback and accepted rationale. Update affected knowledge and the
   existing work item; report actual evidence/limits and a bounded next action.
