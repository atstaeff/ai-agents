# Agent Routing

Reuse a known matching Herdr context; otherwise check executable availability once.
Use Herdr when available and usable under the [execution policy](../../../toolkit/HERDR.md);
report a concrete gap before fallback. Small tasks stay in the current applicable pane.
Read detailed policy only when readiness, routing or dispatch is uncertain.

1. Use the current request and available metadata. A clear small task stays in this
   session. Select one skill for the next unresolved activity; load another only when
   that skill or the task exposes a different uncertainty. Do not traverse the catalog.
2. For substantial work, delegate useful independent ready deliverables or review by default
   when setup/integration cost is justified. Confirm supported tools and authorization;
   otherwise apply the guidance directly. Dispatch ready siblings before waiting on one.
   Complex judgment requires a strong approved model with high reasoning; bounded
   execution uses economical proven models. Use native commands for mechanical dispatch.
   Verify effective model/effort, fill available capacity with independent ready work and
   reduce dispatch under resource, rate, budget or review pressure. All leads/workers share
   one dispatch allowance; request a slot before spawning children. Set bounded retries.
3. Give the specialist outcome, relevant source revisions/pointers, write scope, acceptance,
   constraints/required approvals, expected artifact/checks and escalation triggers. Coordinate overlapping work, use isolated
   working directories for writers and name the integrator. Label task/agent/checks panes,
   preserve user focus and reuse matching locations. Do not invent sessions or routes.
4. Inspect artifacts and evidence, then verify the combined behavior. Give a reviewer
   requirements and the diff; seek counterexamples. A second model is not automatic
   independent approval. Native wait/status alone does not establish this task's completion.
   Read-only reviewers return findings, not claimed execution.
5. Preserve shared feedback/handoff at the assignment; keep personal plans private. Never create a mirror
   tracker or treat an available connector as the information owner.
6. Stop repeated ineffective retries at the agreed limit; revise scope/context or escalate
   with evidence. Track available cost/time, review effort, rework and accepted outcome
   before claiming improvement; mark unavailable host measurements explicitly.
