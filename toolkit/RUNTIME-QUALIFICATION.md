# Qualify a host and its model routes

Use this once for an adopted host/configuration, then reuse the evidence for matching
sessions. Keep credentials and private machine paths in local host configuration. The
[compact runtime record](../templates/delivery/runtime-check.md) can live in the existing
private setup record or assignment; no new manifest or tracking system is required.

## What is established today

| Capability | Repository evidence | Adoption evidence still needed |
| --- | --- | --- |
| Catalog and native export shape | Automated metadata, path/link, ownership, permission-format and recovery checks | Native profile/skill discovery in the installed host/version |
| Workbench persistence | HTTP/storage/recovery and late-editor regression tests | Customer editing workflow and permitted storage |
| Herdr execution | Documented native commands and bounded instruction trials | Actual selected target, dispatch, model/effort, interruption and integrated result |
| Model competence/cost | Explicit acceptance and routing policy | Representative task results, review/rework and observed spend/time |
| Knowledge publication | Source/metadata validation, strict build and bounded browser views | Customer source selection, access policy and retrieval task |

Consult CI for the checked revision. A generated adapter or instruction trial does not
establish live host compatibility. Keep untested host/version entries labelled accordingly.

## Qualify capability, then route work

Choose the task class under [Herdr policy](HERDR.md). Resolve it to an actual provider/model
and documented effort setting in the host. Capture configuration evidence once; do not
ask the model to certify its own competence or pay for a new probe on every prompt.

Before adopting a route, use a representative stack task with explicit expected behavior,
a difficult judgment/failure case, and a missing-tool/small-change case. Identify the
important constraints and acceptable review effort before running them. The accountable
owner records whether the route meets those criteria and its known limits. Use a strong
approved model with verified high reasoning for complex judgment and consequential review.
A declared nickname or higher price is insufficient evidence.

Compare cheaper routes on the same bounded task and criteria. Keep observed time, spend,
defects and review/rework; mark unavailable measurements. Adopt the economical route only
when its accepted results meet the task's needs. A failed attempt should produce an
escalation packet with evidence, not repeated blind retries.

## Establish capacity conservatively

The runtime record holds actual limits and observations. Count active work and use the
smallest relevant remaining allowance across machine, provider, budget, independent ready
work and review capacity. Start with one bounded worker if capacity is unknown; increase
in small waves after observed success and headroom. Recheck before another wave and when
resource pressure, throttling, spend or review backlog changes. This is a dispatch decision
using native tools, not a new background scheduler.

## Complete one real host trial

In a disposable customer-authorized project, demonstrate discovery and reference access,
two isolated writers where capacity allows, independent review, interruption/resume and
checks on the combined revision. Preserve one significant decision and recover it in a
fresh session. Verify the intended machine and effective model/effort rather than relying
on UI labels or a completed pane state. Report blocked parts without replacing the target.

Requalify after material changes to host/provider/model, permissions, routing or operating
constraints, or when observed failures contradict the prior evidence. Small catalog wording
changes need only relevant checks. Keep release/merge/deployment authorization separate.
