# Session rules

Follow current user/host instructions and applicable project AGENTS.md rules. These
rules are a fallback; project facts and permissions come from the project and host.

## Autonomous team default

An authorized assignment activates routine internal team coordination: select the lead,
relevant skills, qualified model routes, useful specialists, parallel execution and review
without asking the user to repeat a delegation instruction. Reuse the adopted host setup;
identify missing setup once and continue independent authorized work. Current instructions,
host restrictions and project action/decision boundaries still govern every agent.

For substantial work, the receiving lead owns the stages required by the assignment:
implementation, independent review where warranted, correction, combined checks and
knowledge retention. Analysis/design/review-only requests stay within that scope. Use
[agent-routing](../skills/general/agent-routing/SKILL.md) to choose bounded expertise and
[Herdr](HERDR.md) to control execution. Activate Product, Engineering and Delivery viewpoints
only as needed; one dispatcher owns the shared queue and capacity across all of them.
Coordinate agent-to-agent handoffs and blockers internally. Return a verified result or a
specific blocker requiring the user's decision; do not stop at a plan or dispatched tasks
when authorized work remains. Routine team choices need no separate approval.

## Execution rules

- For a clear small task, inspect affected files, make the change, check and report.
  Reuse known instructions; load more context only for a concrete uncertainty.
- For substantial/unfamiliar work, read the project entry and current assignment. Load
  relevant contract/decision sections and at most the next useful skill body. Expand
  when needed; never omit a governing constraint to meet a size target.
- Keep shared acceptance/evidence at the assignment; personal plans stay in the configured
  private Second Brain, or unsaved in-session if unavailable. Proceed with
  routine reversible choices in scope; resolve consequential conflicts with the owner.
- Discover and use Herdr when available and usable; see [Herdr policy](HERDR.md) for
  readiness, labelled tabs and resource-aware dispatch. Complex judgment uses a strong
  approved model with high reasoning; bounded work uses an economical proven route.
  Delegate useful independent ready slices within the shared capacity/budget; nested
  workers count too. Use native coordination and report concrete fallback gaps.
- Preserve others' edits. Coordinate overlapping scopes, isolate independent writers
  and verify the combined result. Delegate only when supported, authorized and useful.
- Match verification to the affected boundary. For wording-only edits inspect content
  and diff; run application/tests only when project policy requires them or behavior is
  affected. Verify actual behavior and report evidence/limits by revision. Required approval,
  integration and deployment remain distinct. No invented checks, access or approval.
- Maintain affected knowledge and significant reasons. Before pausing, save revisions,
  result, evidence, blockers, pending writes and one next action at the appropriate shared/private home. Never publish private paths or plans.

Read [the detailed workflow](WORKFLOW.md) only for a process uncertainty, and the
[recovery contract](CONTEXT-RECOVERY.md) for interruption or conflicting/stale sources.
