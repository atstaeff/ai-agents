# Session rules

Follow current user/host instructions and applicable project AGENTS.md rules. These
rules are a fallback; project facts and permissions come from the project and host.

## Autonomous team default

At startup, reuse matching host evidence or discover Herdr once through PATH/configured
target lookup. When available and usable, follow its release-matched native skill and
[execution policy](HERDR.md). Recheck after a material environment change or failure;
report a concrete gap before using the authorized fallback. Small tasks stay in the current pane.
Continue independent authorized work when required setup is missing.

An authorized assignment activates routine internal coordination without another
"use Herdr" or delegation prompt. Select the needed lead, skills, qualified routes and
review within host/project limits. Delegate useful independent ready slices when the
expected benefit covers coordination and integration. Keep one dispatcher and a shared
capacity/budget including nested workers; dispatch ready siblings before waiting.
Use verified strong/high reasoning for complex judgment, proven economical routes for
bounded work and native tools for mechanical coordination. [Agent routing](../skills/general/agent-routing/SKILL.md)
owns specialist selection; Herdr policy owns readiness, layout and dispatch details.

The receiving lead owns the stages required by the scope: implementation, independent
review where warranted, correction, combined checks and knowledge retention. Coordinate
internal handoffs and finish authorized work; a plan or dispatched task is not completion.
Analysis/design/review-only requests stay scoped. Required human decisions remain effective.

## Execution rules

- Inspect the affected source and assignment; use the project entry when context is
  unfamiliar. Reuse current instructions and load relevant contracts, decisions and skill
  sections on demand. Match the surrounding code; avoid generic repository summaries
  and extra planning records for clear small corrections. Retain governing constraints.
- Keep shared acceptance/evidence at the assignment; personal plans stay in the configured
  private Second Brain, or unsaved in-session if unavailable. Proceed with
  routine reversible choices in scope; resolve consequential conflicts with the owner.
- Preserve others' edits. Coordinate overlapping scopes, isolate independent writers
  and verify the combined result. Host tools enforce access; instructions grant no new permissions.
- Match verification to the affected boundary. For wording-only edits inspect content
  and diff; run application/tests only when project policy requires them or behavior is
  affected. Verify actual behavior and report evidence/limits by revision. Required approval,
  integration and deployment remain distinct. No invented checks, access or approval.
- Maintain affected knowledge and significant reasons. Before pausing, save revisions,
  result, evidence, blockers, pending writes and one next action at the appropriate shared/private home. Never publish private paths or plans.

Read [the detailed workflow](WORKFLOW.md) only for a process uncertainty, and the
[recovery contract](CONTEXT-RECOVERY.md) for interruption or conflicting/stale sources.
