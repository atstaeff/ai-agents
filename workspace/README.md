# AI Agents project workspace

This repository maintains a portable agent/skill catalog, runtime exporters and a local
work-record toolkit. The goal is reliable collaboration from shared sources across
people, sessions, models and hosts. Read the detailed
[workspace concept](../toolkit/WORKSPACE-CONCEPT.md) for the full information model,
delivery flow, configuration, migration and publication boundary.

## Entry points

- [Run this repository's workflow](../toolkit/REPOSITORY-WORKFLOW.md): setup, OpenCode startup and a repeatable process replay.
- [Pilot observation](../toolkit/evaluations/workspace-pilot-20261022.md): actual local results and unverified boundaries.
- [Workspace configuration](workspace.yml): actual repository locations and checks.
- [Working agreement](working-agreement.md): instructions, review and completion.
- [Stakeholders](stakeholders.md): accountable roles and permitted contact.
- [Operating model](../toolkit/OPERATING-MODEL.md): outcomes and decision ownership.
- [Recovery contract](../toolkit/CONTEXT-RECOVERY.md): continue from current sources.
- [Decision index](decisions/README.md): rationale for repository-wide choices.
- [Iteration reports](iterations/README.md): report convention, created only when needed.

An assigned GitHub issue owns its current plan and acceptance; the PR owns implementation
and checks. A direct maintenance request already represented by an open PR keeps its
bounded plan and handoff there. A larger direct request without a tracker assignment may use one local
`workspace/work/` record. Local work and archives are ignored by default and are not
published by the knowledge views. Do not copy private chat or customer notes here.
General reusable instructions remain in `toolkit/`, `agents/` and `skills/`.
