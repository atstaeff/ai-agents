# Why organize AI work this way?

A team needs clear assignments, decision rights and enough shared evidence to continue
work across people, sessions and hosts. Reusable expertise helps when it can be selected
without copying customer facts into every profile.

The [operating model](concept.md) gives each source an owner. Root `AGENTS.md` links the
project facts and process, usually in `PROJECT.md` and `CONTRIBUTING.md`. The designated
issue or ticket owns shared scope, acceptance and evidence links. Its PR records the
implementation and review; project knowledge preserves current behavior and significant
reasons. Personal execution plans remain private or explicitly unsaved in-session.

Start with [one real outcome](getting-started/quick-start.md), reuse existing systems and
load only the relevant guidance. No YAML manifest, workspace hierarchy or fixed agent
team is required. Add a decision record when a significant choice arises and update
knowledge when verified behavior changes.

Use a product, architecture or delivery leader and bounded specialists where coordination
helps. Configure models in the host and judge the setup on actual tasks: accepted outcomes,
review effort, rework and recovery. Catalog size and the number of agents do not establish
a productivity improvement. See [orchestration](getting-started/orchestration.md) and the
[source ownership map](architecture.md).

For an outcome without a code change, retain its result and review at the assignment
and linked knowledge source.
