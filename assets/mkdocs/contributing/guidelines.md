# Catalog guidelines

Keep core instructions actionable and concise. Describe concrete selection situations
in frontmatter. Respect existing project technology and use abstractions or dependencies
only where they solve a demonstrated problem. Keep shared workflow in one place.

Preserve feedback and require evidence for completion. Distinguish a verified result
from a proposed change. Protect private notes and secrets. See [contributing](index.md)
and the [shared workflow](../getting-started/workflow.md).
