# Why this structure

The catalog separates reusable guidance from project-specific context. Short English
entries and common frontmatter support selection; runtime adapters handle the fields
that differ between OpenCode and Copilot. Detailed examples stay available on demand.

One work record reduces duplicate proposal, task and feedback documents. Small edits
need no record. A local dashboard lets humans comment on the same file agents update.

The design keeps dependencies small and preserves existing project technology.
It makes no claim to be the only catalog or to guarantee autonomous model behavior.
See [architecture](architecture.md) and [runtime compatibility](getting-started/installation.md).
