Herdr and model routing​

The authorized assignment covers routine internal team coordination within project/host limits. Leads choose useful specialists, model routes, layout and parallel work automatically, then follow required review, correction, checks and knowledge retention through completion. Do not require the user to repeat delegation instructions. Keep analysis/design-only work within its requested scope. Configure actual host/model routes and limits once, reuse matching evidence and report only concrete setup gaps or decisions that need the user.

Use Herdr when its executable and selected server are available within project/host permissions. Reuse matching sessions and load its release-matched native skill through herdr --skill when supported. Respect managed-pane guards; outside automation needs an explicitly selected authorized target. An installed binary alone does not identify it.

For substantial work, delegate useful independent ready slices by default when the benefit justifies coordination. Dispatch siblings before waiting; keep dependent/overlapping work queued. One dispatcher allocates capacity/budget across leads and all nested workers. Group isolated writer worktree workspaces with the project. Reuse labelled Control/Work/ Review tabs; separate agent, nonconflicting checks and service/log panes without stealing focus. Use native state/notifications and bounded reads/waits; verify the returned artifact and task revision before accepting it. No additional fleet tool is required for native Herdr dispatch. Fill free capacity within machine, provider, cost and review limits. If unavailable, state the concrete gap and continue independent work through the authorized host.

Use strong approved models with high reasoning for complex judgment, architecture, decomposition, integration conflicts and consequential review. Use economical proven models for bounded specialist work and native commands for mechanical coordination. Verify effective model/effort in the harness; report a missing required route instead of silently downgrading complex work. Resolve actual routes from local host settings. The Herdr guide is an evolving reference; the local rules in this section define this project's preference unless a different pinned policy is explicitly recorded above.

Coordination and review​

Identify the accountable human, active contributor, bounded write scope, dependencies and integration owner at the assignment; roles may be combined. Isolate independent writers in separate branches/working directories and agree shared contracts first. Coordinate overlapping files through the project's effective claim/handover mechanism; serialize overlap when none exists. Preserve human edits and reread shared records before writes. Delegate only when supported, authorized and useful.

Start with one active increment. Preserve intervening edits and human feedback. Capture significant rationale when it arises and update affected current knowledge from evidence. Resolve consequential conflicts with the owner in PROJECT.md. Follow review requirements and actual action permissions; a plan grants no merge/deployment authority.

Run actual checks on the combined revision, including affected behavior and important failure cases. Required reviews apply to the current revision. Report unrun or blocked checks and keep accepted, integrated, deployed and measured outcomes distinct.

Report the change, actual checks and remaining gaps. Save the bounded handoff described in PROJECT.md before switching sessions. Shared artifacts use English; never invent results, approvals, capabilities or successful writes.
