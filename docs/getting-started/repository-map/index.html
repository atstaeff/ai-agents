Engineering toolkit guide

Start at AGENTS.md. This directory contains reusable guidance and data; tools/ contains executable implementations. Read the next relevant page, not this whole directory at the start of each session.

Repository responsibilities​

LocationPurposeExample
Root AGENTS.mdShort AI entry, essential boundaries and source linksWhere to read project scope and process
PROJECT.md / CONTRIBUTING.mdThis project's facts / contribution processGoals, owners / checks and skill selection
agents/ / skills/Reusable roles / actionable proceduresReviewer / review method
toolkit/Reusable engineering model, adoption and tool documentationHow any project retains decisions
knowledge/Durable facts and decisions about this repositoryWhy this catalog uses private plans
templates/Copyable starting documentsADR, request or architecture review
examples/ / reference-repos/Runnable demonstrations / worked projects / illustrative codeDecision graph / document portal / architecture patterns
tools/ / tests/Executable local tooling / behavior checksRuntime exporter / export protection tests
website/Docusaurus source, configuration, navigation and publisherSource-to-page mapping
docs/Compiled GitHub Pages outputGenerated HTML and assets

Knowledge is project memory, not another skill library or personal task store. A customer project owns its own facts and ADRs; they do not belong in this catalog's knowledge folder. Private plans stay in the user's permitted Second Brain, or unsaved in-session when unavailable. The shared result remains understandable without access to those plans.

catalog-domains.json, catalog-presets.json and catalog-aliases.json define catalog organization, native export selections and retired-name replacements. openapi.json describes the local API; workspace.schema.json supports optional existing YAML setups. examples/ contains worked documentation and evaluations/ records dated observations with evidence and limits. They are reference material, not mandatory startup context.

Source and published view​

Keep each document at one editable owner. Docusaurus can publish Markdown from toolkit, knowledge, agents and skills without moving or copying their maintained sources. The website guide explains the mapping. Root docs/ is reserved for compiled Pages output; website/ already provides a separate Docusaurus source directory.

AGENTS.md may link a maintained Docusaurus process URL for other projects. Keep essential boundaries and project-specific commands locally, identify the applicable source revision or documentation version, and read the relevant linked content explicitly. A URL alone does not inject its contents into an AI session; browsing may be unavailable and a deployed site can lag a checkout. Follow the existing remote documentation template and project concept when adopting central guidance.

Preserve host entry filenames: .github/copilot-instructions.md, path-specific .github/instructions/*.instructions.md, reusable .github/prompts/*.prompt.md, and CLAUDE.md. Their contents can point to canonical guidance; do not rename these entry files to imitate a repository's own documentation naming scheme.

Canonical source: toolkit/README.md.
