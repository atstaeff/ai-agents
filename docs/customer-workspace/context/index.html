Compatibility reference. New projects start at AGENTS.md. Personal execution plans belong in the configured private Second Brain; the structures below are optional existing-layout or shared-team examples, not requirements.

Alpenblick Services document portal

Fictional customer example. CUSTOMER_* URLs are placeholders.

Outcome and value chain​

Service staff need one reliable document reference for each upload attempt, including retries. The business flow is document intake, validation, processing, case assignment and a staff decision. Technical success supports the business goal: fewer duplicate cases and less manual cleanup.

Success for the worked increment means a retry reuses the same document reference; a deliberate new upload can still create a separate document. Production impact needs customer measurements; this example provides no measured business result.

Project tooling configuration​

Read workspace.yml before selecting tools or creating shared records. It defines the authoritative work, review, knowledge, decision, iteration and communication locations. This example selects GitHub. Replace those values on adoption; a Jira ticket can own the entire plan with a linked GitHub PR and no mirror issue.

The working agreement defines ready/review/done and permitted actions; stakeholders names decision makers and contacts. If a wiki owns knowledge, this workspace can remain a compact index. Unavailable access means an unsent proposed update, never an automatic switch to another system.

Working entry points​

  • Project configuration: authoritative tools and locations.
  • Working agreement: delivery, acceptance and communication rules.
  • Stakeholders: who decides and reviews.
  • Upload process draft: relevant domain knowledge.
  • Decision draft ADR-0001: rationale and alternatives.
  • Dependent decision draft ADR-0002: concurrency and recovery.
  • Iteration I1 draft: concise outcome report.
  • Knowledge map: generated index, statuses and explicit relationships.

Keep the current project goal here. Keep each live plan in its GitHub issue. Load individual decision and process documents only when relevant. The documentation site publishes selected entry pages and durable knowledge directories. Local work, archives, generated previews and exports are excluded by the publication allowlist. A reserved compiled docs/ directory contains generated output; AI work uses the Markdown sources. See the Docusaurus integration guide before publishing.
