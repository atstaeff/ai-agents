Engineering with AI

Turn a product need into a verified change, then retain the knowledge needed to operate and improve it. People own priorities, acceptance and consequential decisions. AI leads coordinate bounded work; specialists contribute implementation and evidence.

Start with a project map​

Every adopted project has an AGENTS.md entry linking its purpose, boundaries, responsible people, delivery process, tools, commands and knowledge. Keep facts in their existing homes: PROJECT.md, CONTRIBUTING.md, repository Markdown or an accessible adopted web source. The starter provides a complete example. Record which version of a central process applies. Read relevant linked content explicitly.

The team can continue from shared sources without accessing a personal vault. Use a shared execution plan only when collaborators depend on its steps. Customer data policy governs all storage and model use. No particular folder name, YAML manifest or extra tracker is required.

The value stream​

Use the smallest complete increment. A routine correction can move directly from the request to implementation and relevant checks; it needs no new planning document.

The assignment is the coordination home throughout. The PR links its evidence. Decisions are captured when they arise and reconciled against the implemented result. Completed plans remain historical at their original home; accepted decisions retain replacement links. See the working contract, quality standard and knowledge lifecycle for the relevant detail.

Leads and specialists​

These are responsibilities, not a required headcount. A small task can use one session. For substantial work, activate the lead viewpoints needed by the outcome and name one integrator.

AI roles propose; the project's accountable humans retain decision rights. Leaders share the assignment, interfaces and durable knowledge rather than their entire conversations. Use orchestration for native Herd commanders, specialist packets, concurrency and model selection. A role description alone starts no process and grants no tools.

Work efficiently​

Load the project entry, current assignment and next relevant skill. Search a scoped area and expand for a concrete uncertainty. Keep large examples and reference guides on demand. Use Herdr whenever available and usable, with labelled tabs and isolated writers. Use an economical evaluated model for a well-defined specialty; complex judgment, architecture, integration and consequential review require a strong approved model with high reasoning. Native commands handle mechanical coordination. Escalate a failed approach with its evidence rather than repeating blind retries or increasing the whole team's context.

Parallelize independent slices with clear contracts and isolated writers. Account for coordination cost and provider limits; a larger team is useful only when accepted results arrive sooner without excessive rework. Observe time to accepted change, review effort, defects, model cost and resource use. Model price and token counts alone do not measure value.

Adopt incrementally​

  1. Link the project's real sources from its AGENTS.md.
  2. Deliver one assignment with the relevant catalog preset.
  3. Use available Herdr; add a team when independent work justifies it. Other host/fleet integrations remain available for the adopted environment.
  4. Publish selected shared knowledge through Docusaurus; use bounded graph views for dependencies.
  5. Inspect one completed change and remove friction before expanding the process.

Ponytail and Graphify are optional native tools with distinct jobs: reduce unnecessary implementation and retrieve useful dependency context. The repository's knowledge map publishes curated project records. The optional local workbench manages files; it runs no models or team scheduler.
