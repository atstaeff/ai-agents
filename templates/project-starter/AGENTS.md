# Engineering collaboration entry

## Project sources

For substantial work, read project context and the contribution process, then only the
detail relevant to the assignment. A clear small change can proceed from affected sources.

| Need | Source |
| --- | --- |
| Vision and goals | [Project](PROJECT.md#vision-and-goals) |
| Stakeholders and decision rights | [Responsibilities](PROJECT.md#responsibilities) |
| Scope and constraints | [Scope](PROJECT.md#scope-and-boundaries) |
| Process and relevant skills | [Contributing](CONTRIBUTING.md#working-process-and-skills) |
| Repositories, code locations and work/review homes | [Project sources](PROJECT.md#key-sources-and-links) |
| Tools, integrations and access | [Project tools](CONTRIBUTING.md#tools-and-access) |
| Setup, build and verification commands | [Commands](CONTRIBUTING.md#setup-and-checks) |
| Current knowledge and decision history | [Knowledge](PROJECT.md#current-knowledge-and-decisions) |

Use existing equivalent files when they own the information. Binding process is local
CONTRIBUTING.md unless its policy adoption section names an external source and explicit
adopted SHA/version. Read that adopted body; a link to an evolving technique or reference
does not adopt its policy. If a required source is unavailable, report the exact gap and
continue independent authorized work. Links do not grant access.

## Work and retain

Follow [CONTRIBUTING.md](CONTRIBUTING.md) for execution, coordination, tools, verification
and review. Load relevant skill bodies explicitly; a link does not install a skill.

Keep shared outcome, acceptance and coordination at the assigned work item. Keep personal
steps in the configured private Second Brain when project policy permits, or unsaved
in-session if unavailable. Share a sequence only when collaborators need it.

Preserve human edits and significant decision reasons. Update affected project knowledge
from verified behavior. Before pausing, save revisions, result, evidence/limits, blockers,
pending writes and one next action at the appropriate private or shared home; the shared
handoff must let a teammate continue without private notes.

Use English for shared artifacts and the user's language in conversation. Current
instructions, project rules and actual host permissions govern actions.
