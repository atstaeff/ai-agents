# Project templates

Copy only the artifact the assignment needs, adapt it to the project's existing format
and keep it at the authoritative home. A ticket section or PR body can contain the whole
record. These templates are prompts for concrete evidence, not extra mandatory documents.

| Situation | Template | Home |
| --- | --- | --- |
| Start with minimal project overhead | [Lean starter](lean-project/README.md) | Agent entry, project map, contribution guide and one tooling map |
| Capture an opportunity | [Ideas](knowledge/ideas.md) | Existing idea intake or optional workspace list |
| Develop a concept or feature contract | [Concept/spec](knowledge/concept.md) | Designated specification/knowledge home |
| Preserve product/process rationale | [General decision](knowledge/decision.md) | Designated decision home; inline initially |
| Maintain current behavior | [Current knowledge](knowledge/current.md) | Existing project docs or knowledge space |
| Coordinate a normal increment | [Compact assignment](delivery/assignment.md) | Existing issue or ticket |
| Learn from a significant/repeated incident | [Incident review](quality/incident-review.md) | Existing incident system or optional incident space |
| A new product/project request | [Project brief](project/project-brief.md) | Existing intake or assigned work item |
| Change an existing scope or contract | [Change request](project/change-request.md) | Current assignment and its decision owner |
| A significant choice needs rationale | [Architecture decision](architecture/decision.md) | Designated ADR space |
| Review boundaries and tradeoffs | [Architecture review](architecture/architecture-review.md) | Existing PR/review or linked review record |
| Make a quality requirement measurable | [Quality scenario](architecture/quality-scenario.md) | Existing requirements or architecture source |
| Larger local work has no assigned tracker | [Local work record](delivery/work-item.md) | Optional `workspace/work/` |
| Hand off a bounded delegated scope | [Delegation brief](delivery/delegation.md) | Existing assignment or host handoff |
| Close an actual iteration | [Iteration review](delivery/iteration-review.md) | Designated project update |
| Record checks and practical gaps | [Verification evidence](quality/verification.md) | Existing PR/check evidence |
| Prepare an operational release | [Release readiness](quality/release-readiness.md) | Existing release/change process |
| Resume in a fresh session | [Bounded handoff](customer-workspace/workspace/handoff.md) | Existing work-item section |
| Adopt the workspace in a project | [Customer starter](customer-workspace/README.md) and [setup prompt](customer-workspace/SETUP-PROMPT.md) | Customer-owned sources |
| Add reusable expertise | [Skill](catalog/skill-template.md) or [agent](catalog/agent-template.md) | Canonical catalog |

State unknowns and missing evidence explicitly. Preserve human-owned text and actual
decision status. Do not fill approval, successful checks or deployed results merely to
complete a template. Use the [quality standard](../toolkit/QUALITY-STANDARD.md) and
[operating model](../toolkit/OPERATING-MODEL.md) for the applicable completion criteria.
