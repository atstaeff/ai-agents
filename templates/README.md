# Project templates

Copy only the artifact the assignment needs, adapt it to the project's existing format
and keep it at the authoritative home. A ticket section or PR body can contain the whole
record. Fill the sections that answer a real question; remove unused prompts. Personal
plans stay private; shared outcomes and coordination stay at the assignment.

## Product and stakeholders

| Situation | Template | Home |
| --- | --- | --- |
| Capture an opportunity | [Ideas](knowledge/ideas.md) | Existing ideas intake |
| A new product/project request | [Project brief](project/project-brief.md) | Existing intake or assigned work item |
| Agree a bounded outcome and acceptance | [Assignment](delivery/assignment.md) | Existing issue/ticket |
| Change an existing scope or contract | [Change request](project/change-request.md) | Current assignment and its decision owner |
| Share progress or request a decision | [Stakeholder update](project/stakeholder-update.md) | Existing assignment or authorized communication channel |

## Knowledge, setup and expertise

| Situation | Template | Home |
| --- | --- | --- |
| Preserve current behavior or operating knowledge | [Current knowledge](knowledge/current.md) | Existing project knowledge |
| Explain a significant product/process choice | [General decision](knowledge/decision.md) | Designated decision space |

State unknowns and missing evidence explicitly. Preserve human-owned text and actual
decision status. Do not fill approval, successful checks or deployed results merely to
complete a template. Use the [quality standard](../toolkit/QUALITY-STANDARD.md) and
[operating model](../toolkit/OPERATING-MODEL.md) for the applicable completion criteria.
