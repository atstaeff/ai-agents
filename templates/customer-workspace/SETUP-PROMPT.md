# Set up AGENTS.md collaboration for people and AI

Use this prompt in a coding agent working on the target project. Supply a reference
checkout/revision or accessible source URLs. References:
[adoption](../../toolkit/ADOPT-PROJECT.md), [project concept](../../toolkit/PROJECT-CONCEPT.md),
[team starter](../project-starter/README.md), [instruction variants](../agent-instructions/README.md)
and [repository license](../../LICENSE).

## Prompt

Set up this project for several people and AI sessions to collaborate through AGENTS.md
and authoritative shared sources. Use English for shared artifacts and the user's
language in conversation. Preserve existing project rules, human wording and source ownership.

Inputs: current project and explicitly scoped repositories; AI Agents reference URL or
checkout/revision; known tracker/board and central documentation URLs if available.
Use existing authorization for routine work. Do not invent contacts, source links, checks,
permissions, approvals or successful writes.

1. Inspect applicable instructions, README/project context, source state, CI, architecture,
   current knowledge and decisions. Locate real work/review homes and the current assignment.
2. Use the reference toolkit's AGENTS.md project model. Merge a collaboration contract into
   the project's actual AGENTS.md and verify the selected host discovers it. Choose the
   team, existing-repository, remote-docs, multi-repository or component template as appropriate.
3. Link vision/goals/success signals; stakeholders and decision/acceptance roles; scope,
   exclusions and constraints; the process; actual work/review homes; current knowledge and
   decision history. Reuse existing pages. PROJECT.md and CONTRIBUTING.md are defaults,
   not required names. Require no project.yaml, TOML file or workspace hierarchy.
4. If web documentation owns a source, explicitly instruct the agent to read its content.
   Pin shared policy to an actual source revision or maintained version. Record the version
   used. Declare a local fallback only with known provenance; identify required unavailable
   URLs and blocked work. Continue independent authorized work without pretending access.
5. Define the adopted workflow, actual setup/check commands, relevant skill selection,
   review and action boundaries in the process source. Skills supply reusable procedure;
   a link does not install them or grant tools. Load only relevant bodies and references.
6. Establish one authoritative work item/live plan per assignment, with an accountable human,
   writer scope, dependencies and integrator. For parallel delivery, isolate working
   directories, agree shared contracts and use the project's effective claim/handover
   mechanism. Serialize overlapping scopes when such coordination is unavailable.
7. Reuse current knowledge and decision homes. Add only useful ideas, concepts, current
   contracts, significant rationale or incident records. Preserve accepted reasons and
   link replacements; completed plans stay historical at their work home. Create no empty
   folder hierarchy or per-agent knowledge copy.
8. If documentation is published with Docusaurus, select the canonical Markdown sources and
   provide Project, Process, Knowledge and Decisions navigation. Keep private/local work,
   exports and generated previews outside publication. Maintain the original sources once.
9. Check filled facts/roles and source links; run actual affected checks. Exercise one
   bounded assignment, a fresh-session recovery and an unavailable-source case. Before
   expanding concurrency, exercise overlapping-work handover and combined verification.
   Distinguish structural checks, model observations, host discovery and actual integrations.
10. Report changed sources, actual evidence, remaining gaps and one next action at the
    existing work home. Save revisions, result, checks/limits, blockers and pending writes
    for recovery. Respect current review, merge/deployment and communication authorization.

If old tools depend on YAML configuration or workspace/ workbench records, preserve their
behavior and data. Keep optional compatibility examples separate from the default entry;
do not silently delete records or leave contradictory sources.
