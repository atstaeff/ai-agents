Read product constraints and each affected repository's applicable AGENTS.md and process.
Keep repository-specific commands and implementation knowledge in that repository.
The product map owns cross-repository contracts and integration order. Resolve conflicts
with the accountable owner; do not silently override another repository's rules.

## Plan and coordinate the increment

Keep one parent assignment with end-to-end acceptance and dependency/integration order.
Use child assignments only for genuinely bounded owned increments; do not mirror plans.
Keep personal steps in the configured private Second Brain, subject to project policy;
use an unsaved session plan if unavailable. Share only the execution sequence collaborators
need, at one agreed home linked from the parent assignment.
Identify the accountable human, contract owner, bounded writers, reviewer and integrator.
Agree interface revisions, compatibility, rollout and recovery before dependent changes.

Use separate branches/working directories. Coordinate overlapping scopes through an
actual shared claim/handover mechanism; serialize overlap when no mechanism exists.
Delegate only through supported authorized host capabilities. Preserve others' work.

## Verify the product result

Record a tested revision for every affected repository. Check consumer/provider contracts
and the combined user-visible flow. Integrate in the agreed order under actual action
permissions. A successful individual PR is not a completed cross-repository feature.
Report partial integration, blocked dependencies and unverified release steps explicitly.

## Knowledge and recovery

Maintain affected repo knowledge and product contracts at their owners. Preserve
significant decisions and cross-repository links. Save result, all relevant revisions,
evidence/limits, blockers, pending writes and the next shared action in the parent assignment.
Keep personal resume notes at the private planning home.
A new session verifies current product and repository sources before continuing.
