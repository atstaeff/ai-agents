# Project process

Adapt these steps to the project's actual lifecycle. Their numbers are reading order,
not mandatory gates. Select relevant steps for the assignment and revisit them when
scope or evidence changes. Do not load every step at startup or create a record per step.

| Situation | Read | Result at its existing home |
| --- | --- | --- |
| Outcome or boundaries are unclear | [01 Clarify](01-clarify.md) | Agreed scope and observable acceptance |
| Design, dependencies or coordination need work | [02 Plan](02-plan.md) | Bounded approach, contracts and ownership |
| Implement an authorized change | [03 Build](03-build.md) | Reviewable increment |
| Assess correctness and readiness | [04 Verify](04-verify.md) | Revision-specific evidence and gaps |
| Integrate, retain knowledge or hand over | [05 Integrate and retain](05-integrate-retain.md) | Authorized result and recoverable knowledge |

## Shared collaboration rules

PROJECT.md and CONTRIBUTING.md at the adopted project root own project facts, tools,
commands, review requirements and action boundaries. Resolve these files during adoption.
Step pages own phase-specific procedures. Link the owner instead of copying its policy.

An assigned outcome authorizes routine internal coordination within project/host limits.
Use Herdr when installed and usable, following its installed release-matched instructions.
Report a concrete gap before using an authorized fallback. Choose required leads and
delegate independent bounded work when expected benefit exceeds coordination/review cost.
Use qualified strong/high-reasoning routes for complex judgment and proven economical
routes for bounded tasks. Verify actual model/effort settings; do not invent model IDs.
One dispatcher manages the shared capacity/budget, including children. Give writers
separate scopes/workspaces; coordinate overlaps and label agent/check/log panes clearly.
The lead owns integration, review, correction and combined checks without repeated prompts.

Small corrections can go directly from affected source to build and verification. Existing
mandatory constraints still apply. Analysis-only assignments do not authorize implementation.
Record shared acceptance and coordination at the existing issue/PR; personal plans stay in
the configured private home or unsaved in-session if unavailable. Do not mirror trackers.
Preserve human edits. Required owner decisions, merge/deployment and external communication
follow actual authorization. Instructions grant no access or permission beyond that.

Capture significant decisions when made; finish evidence and status as work progresses.
Before pausing, leave revision, result, checks/limits, blockers, pending writes and one next
action at the shared work home so another teammate can resume without private notes.
