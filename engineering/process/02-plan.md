# 02 — Plan

Use for consequential design, dependencies or substantial coordination. Read acceptance,
affected contracts and relevant decisions. Match the current project process and stack.

1. Compare material alternatives, compatibility, failure/recovery behavior and cost. Use
   [principal engineering decisions](../../skills/architecture/principal-engineer-decisions/SKILL.md)
   when tradeoffs matter. Capture significant reasons as they arise at the project's ADR
   home with actual status and owner; a proposal does not supersede an accepted decision.
2. Agree shared interfaces before dependent work. Give each writer a bounded scope and
   name the integrator. Follow [orchestration](../../toolkit/ORCHESTRATION.md) for independent
   slices, effective claims, isolated workspaces and the shared resource budget.
3. Keep personal execution steps in the privately configured Second Brain, subject to
   project data policy. Resolve vault paths from user-local instructions, never public
   configuration. Reuse the current plan; use the [work template](../../templates/delivery/personal-plan.md)
   when useful. If storage is unavailable, report an unsaved in-session plan and continue
   authorized work. [Obsidian guidance](../../skills/knowledge/obsidian-para/SKILL.md) owns
   saved-plan URI handling. Put a shared sequence only where collaborators need it; do not
   mirror task lists between private plans and trackers.
4. Preserve required plan review: present the concrete current revision and actual feedback;
   reopen after material scope/design changes. Missing review tooling is not approval.
   Follow [plan review](../../toolkit/PLAN-REVIEW.md) only where adopted.

Result: enough design, ownership and planned verification to [build](03-build.md).
[Clarify](01-clarify.md) a blocking owner decision. Clear small changes need no separate plan.
